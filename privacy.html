Privacy Policy for PD Nexus Applications

Effective date: 12 October 2026
Developer: Puneet Dhiman, publishing applications with the text-only creator credit “Envisioned by PD Nexus”
Privacy and support contact: pdnexus.apps@gmail.com

This policy explains how applications envisioned by PD Nexus access, use, store, share, and delete information. It applies to an application when its store listing or in-app privacy screen links to this page. An app-specific notice may provide additional details and controls; where it is more specific, that notice supplements this policy.

1. Applications covered

Covered applications may include FILENZA, Toolzen, APK Pocket, CueFlow, ShelfSaathi, MetroMitra, MultiView Player, Smart System Cleaner, PD Nexus Browser, PD NEXUS Download Manager, Nexus File Manager, PD Nexus Mobile Launcher, PD NEXUS Car Dashboard, PDF Editor, and other applications that link to this policy. Each application keeps its own name, icon, purpose, permissions, and feature set. Features differ by version and platform.

2. Privacy approach

  • Local features process information on the device whenever practical.
  • No application sends feedback merely because a feedback screen is opened.
  • Files, photos, vault contents, browsing history, download history, application lists, location, vehicle data, screenshots, or diagnostic logs are not automatically attached to a feedback email.
  • PD Nexus does not sell personal information or Google user data.
  • Cloud, network, browser, download, sharing, and email features communicate externally only to perform the action the user requests or to provide a clearly identified online feature.

3. Information stored locally

Depending on the application and enabled features, local information may include preferences, themes, layouts, favorites, recent items, task or download queues, browsing data, notes, reminders, media state, file metadata, locally selected folders, recovery records, encrypted vault content, connected-server profiles, and application diagnostics. This information normally remains on the device or Windows account unless the user exports, shares, synchronizes, uploads, emails, or otherwise directs it elsewhere.

Android backup is disabled where an application handles sensitive app-private material that should not be copied through device backup. Exported files and files saved in user-selected folders remain outside app-private storage and must be managed separately.

4. Files and storage

File-management, document, download, media, archive, scanning, cleaning, and PDF features access only the files or storage locations needed for the selected operation and the permissions granted by the user. Applications may read metadata, display content, copy, move, rename, create, export, recover, or delete items when the user initiates or confirms those actions. Some applications retain local recovery records or encrypted trash until the user permanently removes them.

Secure-space or vault features store protected content locally using application encryption and device security where supported. Vault PINs, keys, and protected contents are not sent to PD Nexus for cloud recovery. Losing the device key, clearing app data, or uninstalling may make protected content unrecoverable unless the application provides and the user created an export.

5. Permissions and device capabilities

An application requests permissions only when required for an enabled feature. Depending on the app, these can include selected-file or folder access, camera, microphone, notifications, alarms, nearby devices, Bluetooth, network access, foreground services, vibration, wallpaper, installed-app visibility needed by a launcher, notification-listener access, or device authentication. Permission declarations do not by themselves grant access. Users can deny or revoke permissions in system settings; the related feature may then be unavailable.

Location is not collected merely because a sensor such as a compass or level is used. If a future feature requires location, the application will present an appropriate disclosure and request permission before access.

6. Google Drive access

When a supported app offers Google Drive, connecting an account is optional and requires Google’s authorization screen. The app may request Google Drive access so it can show file and folder metadata and perform user-requested operations such as browsing, downloading, uploading, creating folders, renaming, copying, moving, or deleting Drive items. The connected account’s email address or display name may be stored locally to label the account in the app.

Google access tokens are stored in protected app-private storage on the device. The current FILENZA implementation stores a short-lived Google access token and does not send a Google refresh credential to a PD Nexus server. Disconnecting the account removes the locally stored connection record and token. Users can also revoke access from their Google Account security settings.

Information received from Google APIs is used only to provide or improve the visible, user-requested Drive features. It is not transferred to advertising platforms or data brokers, used for personalized advertising, sold, or used to determine creditworthiness. Humans do not read Google Drive content unless the user deliberately sends specific content for support, disclosure is necessary for security or legal compliance, or the user otherwise gives affirmative permission. Use of information received from Google APIs follows the Google API Services User Data Policy, including its Limited Use requirements.

7. Dropbox and other connected storage

When Dropbox is supported, connecting is optional and uses Dropbox authorization. The application can request account information and file metadata/content permissions needed to browse and carry out user-requested file operations. Access and refresh tokens are stored in protected app-private storage. Disconnecting removes the locally stored connection. Dropbox processes authorization and file requests under Dropbox’s privacy policy.

SMB, SFTP, WebDAV, nearby sharing, PC-link, and similar features connect directly to the server or device configured by the user. Server addresses, account labels, and credentials may be stored locally; secrets are protected using device-backed or application encryption where implemented. Server operators and network providers can process connection metadata and transferred content under their own policies.

8. Browsing, downloads, and online information

A browser necessarily sends addresses, requests, cookies, and other browsing information to websites the user visits and to the browser engine used to render them. Websites, search providers, content-delivery networks, and downloaded content are governed by their own policies. PD Nexus Browser keeps its application profile locally and does not automatically attach browsing history or current page addresses to support messages.

Download applications contact the URLs and servers supplied or selected by the user. Those servers receive ordinary network information, including the device’s IP address and request details. Download URLs, file names, history, credentials, or downloaded files are not automatically sent to PD Nexus support.

Some utility features retrieve reference information such as exchange rates, metal prices, weather, maps, transit data, or software updates. The relevant provider receives the network request and may receive an IP address, requested item, device/browser metadata, and cookies or identifiers controlled by that provider. The app-specific screen or notice identifies the service where practical.

9. Diagnostics, analytics, advertising, and third-party components

PD Nexus does not operate a cross-application advertising profile or a general analytics backend for the covered applications. Some applications use operating-system components or third-party SDKs required for features such as Google Play services, WebView2, ML Kit, maps, media playback, billing, advertising, or crash reporting. Whether a component is active depends on the application version and configuration. Third-party components may process technical data according to their documentation and policies.

Local diagnostics can include application version, operating-system version, device model, feature state, errors, and performance information. Diagnostic logs remain local unless the user explicitly copies, exports, or attaches them. Sensitive file contents, vault contents, passwords, authentication tokens, and full browsing addresses should not be included in support reports.

10. Feedback and support

Feedback & Support opens a message addressed to pdnexus.apps@gmail.com for the user to review. Nothing is sent until the user chooses Send in the email application. The draft may contain editable application, version, platform, and device details. The user can remove this information and controls any attachments.

If the user sends email, the developer and the involved email providers receive the sender address, message, and attachments selected by the user. Support correspondence is used to respond, investigate the reported issue, improve the relevant application, and maintain necessary support records. Do not send passwords, vault PINs, authentication tokens, private keys, or sensitive file contents.

11. Sharing and disclosure

Information is shared only as needed to provide a user-requested feature, with service providers or platforms described in this policy or an app-specific notice, with the user’s direction or consent, for security and abuse prevention, or when required by applicable law. Personal information and Google user data are not sold.

12. Retention and deletion

Local app data remains until it is deleted through available app controls, cleared through system settings, or removed by uninstalling. Some exported files, downloaded files, applied wallpapers, browser downloads, shared documents, backups, or remote cloud files remain outside app-private storage and must be deleted separately.

Disconnecting a connected account removes locally stored tokens and connection records but does not automatically delete files held by Google Drive, Dropbox, or another server. Use the provider’s controls to delete remote content or revoke access. Support correspondence is retained only as reasonably needed to handle requests, investigate issues, meet security needs, and satisfy applicable recordkeeping obligations. Email the support address to request deletion of support correspondence associated with your email address, subject to legal retention requirements.

13. Security

Reasonable safeguards include app-private storage, encrypted secret storage where implemented, secure transport for supported online services, scoped user authorization, review-before-send feedback, bounded temporary files, and explicit confirmation for destructive actions. No storage or transmission method is completely secure. Users should keep their devices updated, use screen locks, verify destinations, and avoid sharing secrets.

14. Children

The covered applications are general-purpose tools and are not specifically directed to children under 13. They do not intentionally request a child to create a PD Nexus account. A parent or guardian who believes a child sent personal information through support can contact the email address below.

15. Policy changes

This policy will be updated before a material new data practice is introduced in an application that relies on it. The effective date will change when revisions materially affect access, collection, use, sharing, retention, or deletion. Store disclosures and app-specific notices must remain consistent with the application’s actual behavior.

16. Contact

For privacy questions, support, access revocation guidance, or deletion requests concerning support correspondence, email pdnexus.apps@gmail.com.
